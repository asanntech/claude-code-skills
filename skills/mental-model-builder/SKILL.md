# メンタルモデル作成スキル

## このスキルの思想

メンタルモデルとは「要素同士の関係を整理した心的表現」であり、目的は **相手への説明** と **自分の理解** の両方を助けることにある。

ここで最も重要な前提が2つある。これを外すと、スキルがかえって理解を歪める。

1. **本質は「図」ではなく「構造化された理解」**。視覚的なダイアグラムは出力形式の一つにすぎない。内容によっては、対比表・短い要約・因果のストーリーのほうが正確なこともある。だから「何でも図にする」のではなく、内容に合った形式を選ぶ。
2. **モデルは確定版ではなく仮説**。早すぎる構造化は、実態に合わないモデルに現実を押し込める危険がある。だから出力は常に「たたき台」として提示し、ズレや抜けを相手が指摘できるようにする。

この2点を、以下の手順すべてに通底させること。

## 手順

### ステップ1：構造を診断する

入力(文章・概念・考え)を読み、要素を抜き出したうえで、**どの種類の関係が支配的か** を見極める。代表的なパターンと見分け方は「表現形式の対応表」を参照。

複数の構造が混在することも多い。その場合は無理に1枚に詰め込まず、主となる構造を1つ選ぶ。情報が多すぎるときは複数のモデルに分割する。

### ステップ2：そもそも構造化すべきかを判断する（最重要）

図やモデルにすることが、本当にこの内容に合っているかをここで一度立ち止まって判断する。次のいずれかに当てはまるなら、無理に視覚化せず、散文・箇条書き・短い要約で返すか、その旨を正直に伝える。

- 要素間に明確な関係構造がなく、単なる列挙にすぎない
- 関係がまだ曖昧で、構造化すると断定しすぎて誤解を招く
- 一文の要約で十分に伝わる
- 数値の大小・推移が主役（それは chart/data_viz の役割であって、このスキルではない）

「構造化しない」という判断も、このスキルの正しいアウトプットである。

### ステップ3：表現形式を選ぶ

ステップ1で診断した構造の性質に基づいて、対応表から形式を選ぶ。「自分は図の人だから図」ではなく「この内容は階層だから構造図」という選び方をすること。

### ステップ4：作成する

- **視覚的な形式**（構造図・フロー・階層・因果図など）を選んだ場合は、visualize ツールを使う。最初に `diagram` モジュールを読み込み、その設計ルール（色・寸法・ラベル）に従う。
- 図はとにかく **疎に** する。1ボックスの情報は最小限にし、詳細は図の外の散文で補う。価値観や前提のような「貫く軸」は、並列のボックスではなく上位/起点として配置すると関係が伝わる。
- **読み筋は上から下に揃える**。方向性のある図（階層・収束・フロー）では、理解の出発点（前提・起点）を上に置き、視線が上→下へ流れるよう配置する。こうすると読み手は読み順のまま理解できる。ただし対比表・関係図・循環図など本来向きを持たない形式は対象外で、同じ階層の並列要素は横並びでよい。
- **非視覚的な形式**（対比表・要約・ストーリー）を選んだ場合は、図にせず文章や表で返す。

### ステップ5：仮説として提示し、更新を促す

出力したら、それで終わりにしない。必ず次を添える。

- このモデルで置いた **前提や解釈** を一言で明示する
- **省いた要素・曖昧だった点** があれば併記する
- 「この構造で合っているか／ズレている部分はどこか」を問いかけ、相手が直せるようにする

これにより、モデルが「更新のきっかけ」として機能し、相手の理解そのものを前進させる。

## 表現形式の対応表

| 内容の性質 | 適した形式 | 見分け方の手がかり |
|---|---|---|
| 順序・手順・時間の流れ | フローチャート | 「まず〜、次に〜」「〜してから〜」 |
| 包含・階層・どこに属するか | 構造図（入れ子のボックス） | 「〜の中に」「〜に含まれる」「〜の一部」 |
| 起点となる価値観や前提が全体を貫く | 上位→下位の階層／収束図 | 「〜を重視して」「〜を前提に」「最終的に〜」 |
| 選択肢のトレードオフ・比較 | 対比表 | 「AとBどちらが」「〜に対して〜は」 |
| 原因と結果・因果の連鎖 | 因果図／ストーリー | 「〜だから〜」「〜の結果〜」 |
| 多対多の関係・ネットワーク | 関係図（ノードとリンク） | 「互いに」「相互に依存」 |
| 関係構造が薄い単なる列挙 | 箇条書き or 短い要約（図にしない） | 並列で順序も包含もない |

迷ったら、対象の「動詞」に注目する。同じ題材でも「手順は？」ならフロー、「構造は？」なら構造図、「どっちがいい？」なら対比表になる。

## 例

**例1（階層・収束型）**
入力：「技術選定では属人化しないことを重視し、学習コスト・既存との親和性・将来性を見て、最後にチームで合意して決める」
診断：起点の価値観が3つの評価軸を貫き、意思決定に収束する階層構造。
形式：上位（価値観）→ 並列の評価軸 → 下位（意思決定）の構造図。
締め：「価値観を起点に置きましたが、軸の重みづけはこの理解で合っていますか？」

**例2（あえて図にしない）**
入力：「好きな映画を3つ挙げて、それぞれ良かった点を書いた」
診断：3つは並列で、相互の関係も順序もない単なる列挙。
形式：図にせず、簡潔な対比表または箇条書きで整理し、無理に構造化しない旨を伝える。

**例3（手順型）**
入力：「リリースはコードレビュー → CI → ステージング確認 → 本番デプロイの順で進める」
診断：明確な時間順の手順。
形式：左→右または上→下のフローチャート。
締め：「各ステップの間に承認や分岐はありますか？あれば追記します。」
