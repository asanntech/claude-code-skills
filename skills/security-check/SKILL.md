# Security Check Skill

OWASP Top 10:2025 に準拠した**一次セキュリティチェック**を行うスキル。コード変更（差分／PR）に対し脆弱性を洗い出し、重要度と CWE 参照を付けて指摘する。品質・可読性中心の `code-review` とは役割を分け、本スキルはセキュリティ専門の一次フィルタとして使う。

## レビュープロセス

1. **対象の特定** — 引数なし→`git diff`（ローカルブランチの未マージ差分）、PR番号/URL→`gh pr diff` を取得
2. **攻撃面の把握** — ユーザー入力点・API境界・DBクエリ・認証/認可・外部通信・ファイル/パス操作を抽出
3. **OWASP観点別チェック** — 下記チェックリストに沿って評価
4. **重要度付け** — Critical / High / Medium / Low（CVSS の考え方ベース）、各指摘に CWE 参照を付与
5. **フィードバック作成** — ローカル出力、PR 指定時は `gh` CLI で Pending 投稿

## OWASP Top 10:2025 チェックリスト

| コード | カテゴリ（英 / 日） | 主な確認内容 |
|--------|----------------------|--------------|
| A01:2025 | Broken Access Control / アクセス制御の不備 | 認可チェックの欠落、IDOR、権限昇格、SSRF（本版で本カテゴリに統合） |
| A02:2025 | Security Misconfiguration / セキュリティ設定ミス | デフォルト設定、過剰な権限、デバッグ有効、CORS 過大、機密ヘッダ漏れ |
| A03:2025 | Software Supply Chain Failures / ソフトウェアサプライチェーンの障害 | 依存の脆弱性・固定漏れ、未検証パッケージ、ビルド/CI の信頼境界 |
| A04:2025 | Cryptographic Failures / 暗号化の失敗 | 弱い暗号・ハッシュ、平文保存/通信、鍵のハードコード、乱数の質 |
| A05:2025 | Injection / インジェクション | SQL/NoSQL/コマンド/LDAP インジェクション、XSS、未パラメータ化クエリ |
| A06:2025 | Insecure Design / 安全でない設計 | 脅威モデル欠如、安全でないフロー設計、レート制限/濫用対策の不在 |
| A07:2025 | Authentication Failures / 認証の失敗 | 弱いパスワード/MFA 不在、セッション管理不備、資格情報の総当たり耐性 |
| A08:2025 | Software or Data Integrity Failures / ソフトウェア・データ完全性の障害 | 安全でないデシリアライズ、未署名更新、信頼できないデータの実行 |
| A09:2025 | Security Logging & Alerting Failures / セキュリティログ・アラートの不備 | 監査ログ欠如、機密情報のログ出力、検知/アラート不足 |
| A10:2025 | Mishandling of Exceptional Conditions / 例外条件の不適切な処理 | 例外/エラー処理の不備による情報漏えい・フェイルオープン |

### 横断チェック（必須）

- **ハードコードされた秘密情報の検出** — APIキー、トークン、パスワード、秘密鍵、接続文字列などがコードや設定にベタ書きされていないか

## 重要度の基準

| 絵文字 | レベル | 目安 |
|--------|--------|------|
| 🔴 | Critical | 容易に悪用可能で、認証回避・RCE・大規模なデータ漏えいなど影響が甚大 |
| 🟠 | High | 悪用された場合の影響が大きい。実装ミスによる脆弱性が明確 |
| 🟡 | Medium | 条件付きで悪用可能、または多層防御の観点で要改善 |
| 🟢 | Low | 影響は限定的だが、ベストプラクティスとして対応推奨 |

## 出力フォーマット

```markdown
## セキュリティチェックサマリー
[全体的なリスク評価を1-2文で / 重大度別の件数]

## 指摘事項

### 🔴 [Critical] タイトル — A0X:2025 カテゴリ名（日本語併記） / CWE-XXX
- **場所**: ファイル名:行番号
- **脆弱性**: 何が問題か
- **攻撃シナリオ**: どう悪用されうるか
- **修正案**: 具体的な対策（コード例）

### 🟠 [High] タイトル — A0X:2025 ... / CWE-XXX
...

## 検査範囲と所見
[何を確認したか。脆弱性が見つからなかった場合もここで明示する]
```

## GitHub PR連携

PR番号またはPR URLが引数として渡された場合、チェック結果をGitHub PRにコメントとして投稿する。
GitHub APIとの連携はすべて `gh` CLI に統一する（MCP GitHub ツールは使用しない）。

### 手順

1. PR情報と差分を取得:

```bash
# PR情報の取得
gh pr view {pr_number} --repo {owner}/{repo} --json number,title,body,headRefName,baseRefName,commits

# 変更ファイル一覧とdiffの取得
gh pr diff {pr_number} --repo {owner}/{repo}
```

2. 差分に基づいてセキュリティチェックを実施

3. 結果を **Pending状態（Start a Review）** で投稿:

```bash
# stdin経由でJSONを渡して投稿（ファイル書き込み不要）
gh api repos/{owner}/{repo}/pulls/{pull_number}/reviews \
  --method POST \
  --input - <<'EOF'
{
  "body": "セキュリティチェックサマリー本文",
  "comments": [
    {
      "path": "src/example.tsx",
      "line": 42,
      "body": "### 🔴 [Critical] タイトル — A05:2025 Injection / CWE-89\n\n脆弱性の説明。\n\n**攻撃シナリオ**:\n（悪用方法）\n\n**修正案**:\n（コード例やアドバイス）"
    }
  ]
}
EOF
```

**重要**:
- `event` フィールドは **絶対に含めない** こと。省略するとデフォルトで `PENDING`（ドラフト）状態になる。`event` に `"COMMENT"` や `"PENDING"` などを指定すると即座に投稿されてしまうので注意。
- `/tmp` へのファイル書き込みは権限で失敗する可能性があるため、必ず `--input -` でstdin経由のヒアドキュメントを使うこと。
- MCP GitHub ツール (`mcp__github__*`) は使用しないこと。`gh` CLI に統一する。

4. 投稿完了後、PRのURLをユーザーに返し、Pending状態であることを伝える

### owner/repo の解決

```bash
# リモートURLから取得
gh repo view --json owner,name --jq '"\(.owner.login)/\(.name)"'
```

- PR URLが渡された場合はURLからパース
- PR番号のみの場合は上記コマンドで現在のリポジトリから取得

### 注意事項

- コメントの `line` にはファイル内の行番号を指定する（diffのposition ではなく）
- 引数なしで呼ばれた場合は、ローカル出力のみ行いGitHubへの投稿は行わない

## チェック時の心構え

- **一次フィルタである** — 網羅的な監査ではなく、変更範囲を OWASP 観点で素早く点検する位置づけ。重大なものを取りこぼさないことを優先する
- **誤検知を最小化** — 確証が持てないものは「potential（要確認）」と明示し、断定しない
- **人ではなくコードを批判** — "このコードは" と書く
- **理由と修正案を添える** — なぜリスクなのか、どう直すかをセットで示す
